# Домашнее задание «Компоненты Kubernetes»

## 1. Упаковка приложения в Helm-чарт

Для развёртывания приложения в разных окружениях используется Helm-чарт.

Чарт должен содержать шаблоны Kubernetes-ресурсов для базы данных, кеша, фронтенда и бекенда.

Количество реплик, параметры CPU и RAM задаются через `values.yaml`.

Для разных окружений можно использовать отдельные файлы:

- `values-dev.yaml`
- `values-stage.yaml`
- `values-prod.yaml`

Это позволит изменять параметры развёртывания без редактирования шаблонов Helm.

## 2. Расчёт ресурсов приложения

| Компонент | Реплики | CPU на реплику | RAM на реплику | Всего CPU | Всего RAM |
|---|---:|---:|---:|---:|---:|
| База данных | 3 | 1 | 4 ГБ | 3 | 12 ГБ |
| Кеш | 3 | 1 | 4 ГБ | 3 | 12 ГБ |
| Фронтенд | 5 | 0,2 | 50 МБ | 1 | 250 МБ |
| Бекенд | 10 | 1 | 600 МБ | 10 | 6 ГБ |
| **Итого** | **21** | | | **17** | **30,25 ГБ** |

Расчёт CPU:

`3 × 1 + 3 × 1 + 5 × 0,2 + 10 × 1 = 17 vCPU`

Расчёт RAM:

`3 × 4 + 3 × 4 + 5 × 0,05 + 10 × 0,6 = 30,25 ГБ`

Для расчётов принято 1 ГБ = 1000 МБ.

**Минимальные требования приложения:**

- CPU: 17 vCPU.
- RAM: 30,25 ГБ.
- Количество Pod: 21.

## 3. Расчёт рабочих нод

Выберем рабочие ноды со следующими характеристиками:

- CPU: 8 vCPU.
- RAM: 16 ГБ.

На каждой ноде зарезервируем ресурсы для ОС, kubelet, container runtime и служебных компонентов Kubernetes:

- CPU: 1 vCPU.
- RAM: 2 ГБ.

Доступные ресурсы одной ноды:

- CPU: 8 - 1 = 7 vCPU.
- RAM: 16 - 2 = 14 ГБ.

Минимальное количество рабочих нод по суммарным ресурсам:

- CPU: 17 / 7 = 2,43 → 3 ноды.
- RAM: 30,25 / 14 = 2,16 → 3 ноды.

Таким образом, без учёта отказоустойчивости достаточно трёх рабочих нод.

## 4. Запас на отказ одной ноды

Для обеспечения отказоустойчивости добавим четвёртую рабочую ноду.

Общие ресурсы четырёх рабочих нод:

- CPU: 4 × 8 = 32 vCPU.
- RAM: 4 × 16 = 64 ГБ.

Ресурсы, доступные приложениям с учётом системного резерва:

- CPU: 4 × 7 = 28 vCPU.
- RAM: 4 × 14 = 56 ГБ.

При выходе из строя одной ноды останутся три рабочие ноды:

- CPU: 3 × 7 = 21 vCPU.
- RAM: 3 × 14 = 42 ГБ.

Сравнение с требованиями приложения:

| Ресурс | Требуется | Доступно после отказа | Запас |
|---|---:|---:|---:|
| CPU | 17 vCPU | 21 vCPU | 4 vCPU |
| RAM | 30,25 ГБ | 42 ГБ | 11,75 ГБ |

Таким образом, по суммарным ресурсам кластер выдерживает отказ одной рабочей ноды.

Для распределения реплик между нодами необходимо использовать `topologySpreadConstraints` или `podAntiAffinity`.

Для базы данных и кеша дополнительно требуется настроить репликацию, механизм переключения при отказе и сохранение данных.

## 5. Служебные ресурсы Kubernetes

Помимо рабочих нод, для отказоустойчивого управления кластером предусмотрим три отдельные control-plane-ноды.

Предварительные параметры каждой control-plane-ноды:

- CPU: 2 vCPU.
- RAM: 4 ГБ.

На control-plane-нодах размещаются:

- kube-apiserver;
- kube-scheduler;
- kube-controller-manager;
- etcd.

Рабочие ноды используют ресурсы для kubelet, container runtime, сетевых компонентов и системных Pod.

Выделенные для рабочих нод 1 vCPU и 2 ГБ RAM являются расчётным резервом. Фактическое потребление зависит от конфигурации кластера.

## 6. Итоговая конфигурация кластера

| Тип ноды | Количество | CPU на ноду | RAM на ноду | Всего CPU | Всего RAM |
|---|---:|---:|---:|---:|---:|
| Worker | 4 | 8 vCPU | 16 ГБ | 32 vCPU | 64 ГБ |
| Control Plane | 3 | 2 vCPU | 4 ГБ | 6 vCPU | 12 ГБ |
| **Итого** | **7** | | | **38 vCPU** | **76 ГБ** |

**Итог:**

Для размещения приложения с возможностью выдержать отказ одной рабочей ноды предлагается кластер из 7 нод:

- 4 Worker - по 8 vCPU и 16 ГБ RAM.
- 3 Control Plane - по 2 vCPU и 4 ГБ RAM.

При отказе одной рабочей ноды оставшихся ресурсов достаточно для работы всех 21 реплики приложения при условии их корректного размещения.

Объём дискового пространства не рассчитывается, поскольку в задании отсутствуют требования к хранению данных. Для базы данных и кеша необходимо отдельно предусмотреть постоянное хранилище и соответствующую политику резервирования.
